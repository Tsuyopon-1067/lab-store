# 購買会計システム 要件定義書

**対象コミュニティ**: 研究室等の小規模コミュニティ  
**文書バージョン**: 1.4  
**作成日**: 2026-03-28

---

## 1. システム概要

研究室等の小規模コミュニティ内で使用する、自販機代替型の購買管理・会計システム。  
利用者はバーコードで本人確認を行い、商品をスキャンして購入記録を残す。  
商品の仕入れは任意の利用者が立て替えて行い、後でコミュニティに精算する。  
購入代金・仕入れ立替金はいずれも後払いで、月次等のタイミングで現金精算する。  
システムは1台のLinux PCで完結し、ブラウザベースのGUIとREST APIを提供する。

---

## 2. お金の流れ

このシステムで管理する債権・債務は以下の3種類。

```
① 購入未払い  : 利用者 → コミュニティ（商品を買った分）
② 仕入て立替  : コミュニティ → 仕入れ者（立て替えてもらった分）
③ 月次精算    : ①と②を利用者ごとに相殺し、差額を現金で授受

  例）山田さんが今月 1,000円分購入 かつ 800円分仕入れ立替
      → 差引 200円を山田さんがコミュニティに支払う

  例）佐藤さんが今月 300円分購入 かつ 1,500円分仕入れ立替
      → 差引 1,200円をコミュニティが佐藤さんに支払う
```

## 3. システム構成

### 3.1 動作環境

| 項目 | 内容 |
|------|------|
| OS | Linux（ディストリビューション不問） |
| 動作形態 | スタンドアロン（1台のPC完結） |
| UI | Webブラウザ（localhost アクセス） |
| ネットワーク | 同一PC内完結（外部公開なし） |
| プロトコル | HTTP（localhost のためHTTPS不要） |

### 3.2 システム構成図

```
同一PC内
┌──────────────────────────────────────────┐
│                                          │
│   ブラウザ（localhost:3000）              │
│     ↕ Webカメラ（ブラウザ Camera API）   │
│                                          │
│   Goサーバ（localhost:8080）             │
│     ↕                                    │
│   SQLite データベース                    │
│                                          │
└──────────────────────────────────────────┘
```

### 3.3 バーコードスキャン方式

- **利用者識別**: PCに接続したUSBバーコードリーダ（キーボード入力エミュレーション）
- **商品スキャン**: Webカメラ＋ブラウザのCamera API（ZXing-js を使用）
  - ZXing-js はJAN（EAN-13）・CODE128・QR等の主要形式に対応

## 4. 利用者・権限

### 4.1 ロール定義

| ロール | 説明 |
|--------|------|
| 管理者 | 全機能にアクセス可能。支払い記録の修正・削除も可能 |
| 一般利用者 | 購買・仕入れ登録・自分の履歴と残高確認が可能（認証不要） |

### 4.2 管理者認証

- 管理画面へのアクセスにはパスワード認証を必要とする
- セッションベースの認証とし、ログイン後は一定時間（デフォルト30分）有効とする
- セッション時間は設定ファイルで変更可能とする
- パスワードはbcryptでハッシュ化してデータベースに保存する
- 初期パスワードはセットアップ時にCLIで設定する

### 4.3 利用者管理

管理者がGUIから利用者を登録・編集・削除する。

| 項目 | 説明 |
|------|------|
| 利用者ID | システム内部ID（自動採番） |
| 氏名 | 表示用氏名 |
| バーコード値 | 利用者識別用（1人につき1つ） |
| 有効フラグ | 退会・一時停止等に使用 |
| 登録日時 | レコード作成日時 |

## 5. 商品・価格管理

### 5.1 テーブル設計（価格履歴分離方式）

```
products（商品マスター）
  └─ id, name, barcode, is_active, note, stock_quantity, created_at

product_prices（価格履歴）
  └─ id, product_id, price, valid_from, valid_to
       ※ valid_to が NULL のレコードが「現在有効な価格」
```

- バーコードと商品は常に1対1で対応する
- 価格変更時は旧レコードの `valid_to` に現在日時を設定し、新レコードを作成する
- 購入履歴は `unit_price` に購入時の価格をスナップショット保存する
- `stock_quantity` は購入時に減算、仕入時に加算される。商品管理画面で直接編集可能

### 5.2 GUI操作（商品管理画面・管理者）

- 商品一覧の表示（有効・無効の切り替え表示）
- 商品の新規追加・編集・有効/無効切り替え
- 価格変更（旧価格の終了＋新価格の登録を自動実行）
- 価格履歴の表示
- 在庫数の表示・直接編集（購入・仕入れによる自動調整に加え、手動修正が可能）

## 6. 機能要件

### 6.1 購買操作（メイン画面）

#### フロー

```
① 利用者バーコードをスキャン（バーコードリーダ）
        ↓
② 利用者を特定・氏名と現在の未払い残高を表示
        ↓
③ 商品バーコードをWebカメラでスキャン → カートに追加
   ※ スキャン失敗時はGUIから商品を検索して手動追加
   ※ カート内の数量はGUI上で増減・削除可能
        ↓
④ 購入確定ボタンを押す
        ↓
⑤ 購入履歴に記録・未払い残高を更新、確認画面を表示
```

#### 機能詳細

- 利用者スキャン後、氏名・現在の未払い残高（購入未払い − 仕入れ立替未精算）を表示する
- 購入確定後、レシート相当の確認画面（購入商品一覧・合計額・更新後残高）を表示する
- 一定時間操作がない場合、セッションを自動リセットし初期画面に戻る

### 6.2 仕入れ登録（仕入れ画面）

任意の利用者が商品を仕入れた際に立替金を記録する。

#### フロー

```
① 仕入れ者のバーコードをスキャン（バーコードリーダ）
        ↓
② 仕入れ者を特定・氏名を表示
        ↓
③ 仕入れた商品をバーコードでスキャン または GUIから手動追加
   ※ 商品ごとの数量を入力
        ↓
④ 仕入れ金額（合計）を確認・メモを入力
        ↓
⑤ 仕入れ登録ボタンを押す
        ↓
⑥ 仕入れ履歴に記録・仕入れ者の立替未精算額を更新
```

#### 記録する情報

| 項目 | 説明 |
|------|------|
| 仕入れID | 自動採番 |
| 仕入れ者ID | 立て替えた利用者 |
| 仕入れ日時 | タイムスタンプ |
| 仕入れ金額（合計） | 実際に支払った合計金額（円） |
| メモ | 領収書の内容・購入場所など任意入力 |

#### 仕入れ明細として記録する情報

| 項目 | 説明 |
|------|------|
| 明細ID | 自動採番 |
| 仕入れID | 親の仕入れレコード |
| 商品ID | 仕入れた商品 |
| 数量 | 仕入れ数量 |
| 仕入れ単価 | 実際の仕入れ単価（円） |

- 仕入れ金額の合計は明細の合計と一致することが望ましいが、端数調整等のため手入力の合計を正とする
- 仕入れ登録時に各商品の在庫数（`stock_quantity`）を加算する
- 仕入れ登録後、管理者は内容の修正・削除が可能。修正・削除時は在庫を正確に調整する

### 6.3 購入履歴閲覧（一般利用者）

利用者が自分のバーコードをスキャン後、自分の購入履歴を確認できる。

- 購入日時・商品名・数量・単価・小計の一覧（明細）
- 期間フィルタ（今月・先月・全期間 等）
- 期間内の合計金額・未払い残高

### 6.4 残高確認（一般利用者）

バーコードをスキャンすると以下を確認できる。

| 項目 | 説明 |
|------|------|
| 購入未払い額 | 未精算の購入代金合計 |
| 仕入れ立替未精算額 | 未精算の仕入れ立替金合計 |
| 差引残高 | 購入未払い − 仕入れ立替未精算（プラスなら支払い義務、マイナスなら受取権利） |

### 6.5 支払い管理（管理者）

購入代金の現金精算を管理者が記録する。

#### 支払い記録フロー

```
① 利用者から現金を受け取る（システム外）
        ↓
② 管理者が管理画面から支払い記録を登録する
   - 対象利用者・支払い金額・支払い日・メモを入力
        ↓
③ 利用者の未払い残高が減算される
```

#### 支払い記録の修正・削除

- 管理者は誤入力に備えて支払い記録を修正・削除できる
- 修正・削除の操作ログを記録し、いつ誰が変更したか追跡できる

### 6.6 仕入れ立替精算（管理者）

仕入れ立替金のコミュニティ → 仕入れ者への支払いを管理者が記録する。

#### 精算記録フロー

```
① コミュニティが仕入れ者に現金を支払う（システム外）
        ↓
② 管理者が管理画面から精算記録を登録する
   - 対象仕入れ者・精算金額・精算日・メモを入力
        ↓
③ 仕入れ者の立替未精算額が減算される
```

- 管理者は精算記録を修正・削除できる（操作ログを記録）

### 6.7 月次精算サマリ（管理者）

管理者が月次精算のために各利用者の収支を一覧で確認できる。

#### 表示内容（利用者ごと）

| 項目 | 説明 |
|------|------|
| 購入合計額 | 期間内の購入代金合計 |
| 購入既払い額 | 期間内に支払い済みの金額 |
| 購入未払い額 | 差引の未払い残高 |
| 仕入れ立替合計額 | 期間内の仕入れ立替金合計 |
| 仕入れ既精算額 | 期間内に精算済みの金額 |
| 仕入れ未精算額 | 差引の未精算残高 |
| **差引請求額** | 購入未払い − 仕入れ未精算（正なら利用者が支払う、負ならコミュニティが支払う） |

- CSVエクスポート（月次精算用）

### 6.8 購入履歴・仕入れ履歴管理（管理者）

- 全利用者の購入履歴・仕入れ履歴を期間・利用者でフィルタリングして閲覧
- CSVエクスポート

### 6.9 バックアップ

- 管理者がGUIからバックアップをいつでも手動実行できる
- 定期自動バックアップ（cronを利用、実行間隔は設定ファイルで変更可能）
- バックアップはSQLite公式のバックアップAPIを使用する
- バックアップ先・世代数は設定ファイルで変更可能

## 9. 非機能要件

| 項目 | 内容 |
|------|------|
| レスポンス | 購買・仕入れ操作のレスポンスは通常1秒以内 |
| データ保持 | 全履歴・支払い記録を永続的に保持する |
| 可用性 | systemd サービスとして登録し、PC起動時に自動起動する |
| セキュリティ | localhost 完結のためHTTP運用。管理者パスワードはbcryptでハッシュ化して保存する |
| 操作ログ | 支払い記録・立替精算記録・仕入れ記録の修正・削除は操作ログを記録する |
| 保守性 | 設定値は設定ファイル（YAML等）で変更可能とする |
| DB安定性 | SQLiteはWALモード（`PRAGMA journal_mode=WAL`）で運用する |

## 10. 技術スタック

| レイヤ | 採用技術 | 備考 |
|--------|---------|------|
| バックエンド | Go（Gin） | シングルバイナリでデプロイが簡単 |
| データベース | SQLite（WALモード） | 単一ファイル・追加インフラ不要 |

| マイグレーション | goose | SQLファイルの連番管理・適用状態の自動追跡 |
| フロントエンド | SvelteKit | ローカル完結用途に適しシンプルに仕上がる |
| バーコードスキャン | ZXing-js | JAN・CODE128・QR等の主要形式に対応 |
| 定期バックアップ | cron（Linux標準） | OS機能で完結 |
| 認証 | セッションCookie ＋ bcryptハッシュ | 管理者のみ |
| プロセス管理 | systemd | PC起動時の自動起動に使用 |

## 11. データモデル（ER概要）

```
users（利用者）
  └─ id, name, barcode, is_active, created_at

products（商品マスター）
  └─ id, name, barcode, is_active, note, stock_quantity, created_at

product_prices（価格履歴）
  └─ id, product_id → products.id
     price, valid_from, valid_to

purchases（購入ヘッダ）
  └─ id, user_id → users.id, purchased_at

purchase_items（購入明細）
  └─ id, purchase_id → purchases.id
     product_id → products.id
     quantity, unit_price

payments（購入代金支払い記録）
  └─ id, user_id → users.id
     amount, paid_at, note
     created_by, updated_by, deleted_at   ← 操作ログ用

restocks（仕入れヘッダ）
  └─ id, user_id → users.id（仕入れ者）
     total_amount, restocked_at, note

restock_items（仕入れ明細）
  └─ id, restock_id → restocks.id
     product_id → products.id
     quantity, unit_price

restock_payments（仕入れ立替精算記録）
  └─ id, user_id → users.id（仕入れ者）
     amount, settled_at, note
     created_by, updated_by, deleted_at   ← 操作ログ用

audit_logs（操作ログ）
  └─ id, table_name, record_id, action（update/delete）
     before_json, after_json, operated_at

admin_sessions（管理者セッション）
  └─ id, token, created_at, expires_at

backups（バックアップ履歴）
  └─ id, filename, created_at
```

### 残高の算出方法

残高はテーブルに持たず、毎回集計クエリで算出する（整合性を保つため）。

```
購入未払い額     = SUM(purchase_items.quantity * unit_price)
                 − SUM(payments.amount)

仕入れ未精算額   = SUM(restocks.total_amount)
                 − SUM(restock_payments.amount)

差引残高         = 購入未払い額 − 仕入れ未精算額
```
