# 本番環境デプロイ チェックリスト

本番環境へのデプロイ前に、このチェックリストをすべてクリアしてください。

---

## 開発フェーズ

- [ ] すべてのバックエンド機能が実装済み
- [ ] すべてのフロントエンド画面が実装済み
- [ ] ユニットテストが実装・実行済み
- [ ] 統合テストが実施済み
- [ ] コード品質チェック（go fmt, go vet）実施済み
- [ ] ログレベルが本番用に調整済み（debug → warning/error）
- [ ] 密度パッケージが削除/非表示化済み

---

## セキュリティチェック

- [ ] 管理者パスワードが設定済み
- [ ] 初期パスワードが変更済み
- [ ] デフォルトユーザーが削除/無効化済み
- [ ] SQL インジェクション対策が実装済み
- [ ] CSRF トークンが実装済み
- [ ] CORS が正しく設定済み（ワイルドカード * ではなく、信頼できるドメインのみ）
- [ ] sensitive な情報が config.yaml などの外部に記載されていない
- [ ] SSL/TLS が設定される予定
- [ ] ファイアウォールルールが確認済み

---

## インフラチェック

### コンテナ・ポート

- [ ] Containerfile が正しく作成されている
- [ ] compose.yaml が正しく構成されている
- [ ] ポート設定が確認済み（backend: 8080内部, frontend: 3000公開）
- [ ] volumes マウントが確認済み（data, backup, config）
- [ ] 依存関係が設定済み（frontend depends_on backend）

### ネットワーク・ファイアウォール

- [ ] ファイアウォールでポート 3000 が開かれている
- [ ] 不要なポートが閉じられている
- [ ] リバースプロキシ（nginx）の設定が完了している（オプション）

### ストレージ・バックアップ

- [ ] data/ ディレクトリが作成済み
- [ ] backup/ ディレクトリが作成済み
- [ ] バックアップスケジュールが設定済み
- [ ] リカバリテストが実施済み
- [ ] データベースダンプが定期的に外部に転送される仕様を確認

---

## 設定チェック

- [ ] config.yaml が環境に応じて調整済み
  - [ ] session.timeout_minutes が本番値（推奨: 30分）
  - [ ] backup.interval_minutes が本番値（推奨: 60分）
- [ ] タイムゾーンが正しく設定されている（TZ=Asia/Tokyo）
- [ ] ログレベルが本番用に設定済み
- [ ] データベースパスが正しい（/app/data/purchase.db）

---

## デプロイ実行

### Linux サーバーへの転送

- [ ] リポジトリが /opt/purchase-system にクローンされている
- [ ] config.yaml が作成されている
- [ ] data/ / backup/ ディレクトリが作成されている

### サービス起動

- [ ] 管理者パスワードが初期化済み
- [ ] Podman（または Docker）がインストールされている
- [ ] podman-compose（または docker-compose）がインストールされている
- [ ] コンテナのビルドが成功している
  ```bash
  podman-compose build
  ```
- [ ] コンテナの起動が成功している
  ```bash
  podman-compose up -d
  ```
- [ ] systemd サービスが登録済み
  ```bash
  sudo systemctl enable purchase-system
  sudo systemctl start purchase-system
  ```

---

## 動作確認

- [ ] フロントエンドが `http://localhost:3000` で表示される
- [ ] ログイン画面が表示される
- [ ] 管理者ログインが正常に動作する
- [ ] ユーザーバーコード認証が動作する
- [ ] 購入処理が正常に記録される
- [ ] 残高照会が正常に動作する
- [ ] バーコードスキャンが動作する
- [ ] 管理画面にアクセスできる
- [ ] 商品一覧が表示される
- [ ] ユーザー一覧が表示される

---

## パフォーマンス・監視

- [ ] ヘルスチェックエンドポイントが応答している
  ```bash
  curl http://localhost:3000/health
  ```
- [ ] コンテナのリソース使用状況が監視可能
  ```bash
  podman-compose stats
  ```
- [ ] ログが適切に記録されている
  ```bash
  podman-compose logs -f
  ```
- [ ] 応答時間が許容範囲内（目安: < 1秒）
- [ ] データベースのサイズが監視可能

---

## ドキュメント・保守性

- [ ] デプロイガイド（本ドキュメント）が読まれている
- [ ] よく使うコマンドが運用チームに周知されている
- [ ] トラブルシューティングガイドが理解されている
- [ ] バックアップ・リカバリ手順が定期的にテストされている
- [ ] 定期的なメンテナンススケジュールが決定されている

---

## ゴーライブ後

- [ ] 24時間の監視・監視が実施できる体制が整っている
- [ ] エラーが発生した場合の連絡体制が確立されている
- [ ] 定期的なログレビュー（日次または週次）が実施される
- [ ] 月次のバックアップリカバリテストが実施される
- [ ] セキュリティアップデートが定期的に適用される
